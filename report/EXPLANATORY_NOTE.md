# Пояснительная записка
## Распознавание нестандартных государственных регистрационных знаков

### 1. Цель и постановка задачи
Решение разработано для полностью офлайн-распознавания российских государственных регистрационных знаков типов `type1` (тип 1), `type1a` (тип 1А) и `type1b` (тип 1Б), а также корректного отсева прочих знаков (`other`). На вход программе передаётся каталог изображений JPG/PNG, на выходе формируется CSV с полями `image;plate_num;plate_type;confidence`. Решение рассчитано на локальное применение и не обращается к внешним API во время распознавания.

### 2. Данные и подготовка датасета
В комплекте находится воспроизводимая синтетическая часть датасета объёмом 5600 изображений: `type1` - 1662, `type1a` - 1729, `type1b` - 1609, `other` - 600. Генерация выполняется собственными скриптами с фиксируемым random seed. Для приближения к реальным условиям применяются перспективные искажения, размытие, шум, изменение яркости, JPEG-деградация и отрицательные примеры.

Для реальных изображений предусмотрен отдельный механизм сбора из открытых источников с проверкой разрешённых лицензий. В `meta.csv` фиксируются путь к изображению, номер, тип знака, `bbox`, четыре угловые точки `quad`, признаки `is_vehicle` и `is_synthetic`, источник, лицензия и условия съёмки. Автоматически предложенная разметка не выдаётся за ручную: происхождение разметки фиксируется в `annotation_audit.csv`, а неизвестные символы обозначаются `#`.

### 3. Архитектура решения
Пайплайн состоит из пяти последовательных этапов:
1. OpenCV формирует быстрые region proposals по геометрии и визуальным признакам.
2. Обученный локальный SVM-фильтр `detector_svm.joblib` отсеивает ложные кандидаты.
3. Найденный знак выравнивается перспективным преобразованием.
4. Определяется тип знака `type1/type1a/type1b/other`; для целевых классов выполняется OCR. Основная OCR-модель `ocr_svm.joblib` использует HOG-признаки и LinearSVC; предусмотрен детерминированный fallback.
5. Постобработка проверяет результат по допустимому алфавиту и маске российского ГРЗ, рассчитывает итоговую уверенность и записывает строки CSV.

Модульное разделение `detect -> rectify -> classify -> recognize -> validate` позволяет заменить отдельные компоненты более тяжёлыми моделями без изменения интерфейса запуска.

### 4. Обучение и локальная валидация
В составе проекта находятся скрипты воспроизведения обучения. OCR SVM обучен на процедурно сгенерированных вариантах допустимых символов. На отдельной синтетической held-out выборке получена accuracy 1.0000 (528 примеров). SVM-фильтр кандидатов на синтетической held-out выборке показал accuracy/precision/recall/F1 = 1.0000 на 720 примерах. Эти показатели отражают только контроль процедурной синтетики и не интерпретируются как качество на скрытом тестовом наборе или реальных камерах.

### 5. Производительность и запуск
Основная команда запуска:
`python main.py --input <catalog> --output result.csv --benchmark`

Контрольный запуск на локальном ПК участника 25.10.2026: обработано 3 изображения, получено 2 детекции, среднее время обработки - **30.63 мс/изображение**. Показатель ниже установленного в задании порога 100 мс/изображение, однако измерение выполнено не на референсном компьютере жюри и поэтому приводится только как локальный замер. Для воспроизводимости сериализованных SVM-моделей в зависимостях зафиксирован `scikit-learn==1.8.0`.

### 6. Ограничения и развитие
Основные ограничения связаны с доменным разрывом между синтетическими и реальными изображениями. Качество может снижаться на очень мелких знаках, при сильном загрязнении, бликах, ночной съёмке, выраженном motion blur и сложном фоне. Поэтому проект предусматривает добавление лицензированных реальных данных и последующее дообучение лёгкого нейросетевого детектора.

Для расширения на другие формы и страны достаточно добавить новые классы, допустимый алфавит и правила постобработки; общий интерфейс решения сохраняется. Проект полностью автономен, веса моделей поставляются вместе с исходным кодом.
